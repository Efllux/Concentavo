# Hosted Concentavo editor

The editor is live at `https://efllux.github.io/Concentavo/` through this repository's `Web app` GitHub Actions workflow. Cloudflare does not host the editor. It saves locally without sign-in. Signed-in publishers can publish each rehearsal room to a separate public GitHub Pages repository (the default), or put all public rooms in separate paths of one shared public repository. Optional editable-room sync uses one private `concentavo-library` repository in either case. The private repository is not a website. The authentication Worker exchanges a login code only; scores travel between the browser and GitHub.

The publish dialog explains both layouts. Separate repositories give each room independent site settings, history and URLs, at the cost of more repositories. The shared layout uses one Pages site and one repository for all public rooms; each room has a stable `/rooms/<room-id>/` URL, but publishing and site settings are shared. Existing published rooms keep their layout and URL. In the shared layout the publisher verifies `.concentavo-rooms.json` at the repository root and the room's own marker before changing files. It checks that the room's page has not changed since the last publish, so an update to another room does not cause a false conflict.

GitHub Free supports collaborators on private repositories, but its Pages sites must be published from public repositories. A private repository used for editable sync is separate from the public website. Concentavo's current sync is scoped to one signed-in account; inviting a GitHub collaborator does not yet make that person's Concentavo dashboard co-edit the same room.

Room settings can require a password for the complete published room. The website contains an encrypted room payload; its name, notes and scores are not embedded as plaintext in the published HTML. Singers enter one password to see the room. A piece with a separate per-piece password still requires that extra password; pieces using the shared room password do not. The editable copy in the app and the optional private sync repository are unchanged. This is shared-password access, not individual singer accounts; the public HTML and ciphertext remain downloadable, and a weak password can be guessed offline. Repository names and URLs may still reveal what a room is called. If a room was published without a password before, its older plaintext files remain in the public repository's Git history; a password on a later version cannot retract them.

## One-time owner setup

1. This repository's Pages source is **GitHub Actions**. The `Web app` workflow builds and deploys `dist/` on pushes to `main`; the first deployment completed successfully.
2. The [Concentavo GitHub App](https://github.com/apps/concentavo) is registered under @Efllux with client ID `Iv23licLoMnFc6twUP93`, homepage and callback `https://efllux.github.io/Concentavo/`, user authorization during installation, webhooks off, and **Administration: write**, **Contents: write**, and **Pages: write** repository permissions. During installation, choose **Only select repositories**, and select existing Concentavo room repositories or a shared public room repository you want to reconnect. GitHub automatically grants an installed app access to repositories the app creates later, so **All repositories** is unnecessary. Existing `concentavo-library` repositories must also be selected for sync; a newly created one is added automatically. The app needs no organization permissions or private key for its user access token flow. GitHub's registration banner suggests generating a private key, but that key is for authenticating as the app; Concentavo does not use installation tokens.
3. The [Cloudflare Worker](https://dash.cloudflare.com/400f29420cd37ec390f637ba65555c18/workers/services/view/concentavo-auth/production/settings#variables) is deployed at `https://concentavo-auth.tight-feather-98c0.workers.dev` with the public `ALLOWED_ORIGIN`, `REDIRECT_URI`, and `GITHUB_CLIENT_ID` variables. In [GitHub App settings](https://github.com/settings/apps/concentavo), generate a client secret and put it directly in the Worker's production variable `GITHUB_CLIENT_SECRET`, with **Secret** selected. Keep it out of chat, repository files, and Actions variables. The checked-in `auth/worker.js` and `auth/wrangler.toml` are the source for future Worker updates; Wrangler can also deploy them after `npx wrangler login` with `npx wrangler deploy --config auth/wrangler.toml`.
4. In [repository Actions variables](https://github.com/Efllux/Concentavo/settings/variables/actions), `CONCENTAVO_GITHUB_CLIENT_ID`, `CONCENTAVO_GITHUB_APP_SLUG`, and `CONCENTAVO_AUTH_URL` are set. After the Worker secret is saved, check **Connect GitHub** in the live editor. The editor still works locally and exports ZIPs if sign-in is unavailable.

The app uses PKCE and a one-time state value. GitHub tokens remain in page memory and are lost when that tab reloads or closes. Users sign in again to resume publishing or syncing. The Worker does not store tokens or room data. Keep the Worker and GitHub App settings under the same maintainer account so they can be rotated together.

## Moving from desktop

In the desktop app, choose **Back up room**. In the web editor, choose **Restore room → Move from desktop** and select the `.concentavo` file. This preserves room and piece IDs. On the first GitHub sign-in, Concentavo verifies the existing practice site's ownership marker before offering to update its URL. **Restore copy** creates an independent room with new IDs and no publishing target.

Before enabling sync, the editor explains that editable scores, including hidden pieces, enter a private GitHub repository. Browser changes save locally first; while the editor is open and signed in, changes sync in the background. If both devices changed the same room, the newer remote room and a local conflict copy remain available for review. A disconnected browser continues to save locally. Git history retains older versions of deleted or changed files.

Local browser storage belongs to the exact site origin. If the editor later moves to a custom domain, users can sign in to load synced rooms there or import a `.concentavo` backup; browser storage does not move automatically.
